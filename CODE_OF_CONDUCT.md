# Code of Conduct

## The short version

Be respectful, be honest about what you did and didn't verify, and assume
good faith. That covers most of it.

## What this looks like in practice

- Disagree with a design decision or a piece of code, not with the person
  who wrote it.
- If you're reviewing a PR, explain the "why" behind a requested change,
  not just the "what."
- If you're submitting a PR, be honest in the description about what you
  tested and how — this project cares specifically about verification
  against a running instance, not just "looks right to me."
- No harassment, personal attacks, discriminatory language, or unwelcome
  sexual attention, in issues, PRs, commit messages, or the project's
  Discord/chat channels if one exists.
- Don't submit PRs generated to farm contribution credit (low-effort
  changes, restyled duplicates of existing work, or anything designed to
  look like more than it is). Report suspected cases of this via an issue
  rather than calling someone out publicly.

## Scope

This applies anywhere the project's contributors interact under the
project's name: the repo itself, issues, PRs, and any linked community
spaces.

## Enforcement

If someone's behavior violates this, open an issue tagged appropriately or
contact a maintainer directly. Maintainers will look into it, and may edit,
remove, or reject contributions, or restrict someone's ability to interact
with the project, depending on severity. Repeated or serious violations can
result in a permanent block from the repo.

Maintainers themselves are held to the same standard — if a maintainer
violates this, raise it the same way.
